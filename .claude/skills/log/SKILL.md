# 최근 판 끊김 로그 요약

`bash .claude/skills/log/summarize.sh` 를 실행한다. 두 판을 비교하려면 `summarize.sh 2`.

출력은 세 부분이다.

1. **설치 상태**: 패치 실패나 설치 오류가 있으면 측정값을 믿기 전에 그것부터 본다.
   이전에 `AccessTools.DeclaredMethod`의 Ambiguous match로 설치가 절반만 된 채 측정한 적이 있다.
2. **요약**: 판 전체 끊김 횟수, 심한 순서, GC 재개 기록.
3. **30ms 넘은 프레임**: 각 끊김 아래에 단계 / 그리기 / 콜백 / 느린 함수 줄이 붙는다.

## 읽는 법

| 줄 | 보는 것 |
|---|---|
| `힙 ±MB` / `정리 N회` | GC 쪽인지 |
| `네이티브 +MB` | 그 순간 리소스를 불러왔는지 |
| `그래픽 +MB` | 화면 버퍼를 새로 잡았는지 |
| `직전 프레임 단계` | 엔진 어느 단계인지 (Update / LateUpdate / FinishFrameRendering) |
| `그리기: 걸러내기 / 그리기 준비` | 컬링인지 Camera.Render 안인지 |
| `그리기 콜백` / `프레임레이트 연출` | 렌더 중 스크립트, 수동 Camera.Render |

## 주의

- 같은 지점에서 **두 판 연속** 나오는지 먼저 본다. 한 번만 나오면 일회성(셰이더 컴파일, 로딩)일 수 있다.
- 필터는 박자마다 켜지고 꺼지므로 "0.0초 전에 필터가 바뀜"은 인과가 아니다. 이미 한 번 속았다.
- 곡 시작 3~8초의 수 초짜리 멈춤은 맵 로딩이다. `SlowScan`을 켜 두었으면 그것이 4초를 먹는다.
